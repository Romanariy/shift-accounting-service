# Пересекающиеся часы и общее предложение студий

## Сайт и бот

В «Предложения смен и услуг» нажмите «Предложить смену», задайте дату, студию и её интервал. «Добавить вторую студию» добавляет отдельные время и фотографии. Допускаются одна или две разные организации, до 10 фотографий суммарно. После сохранения проверяют условия и подтверждают публикацию.

В личном чате бота альбом с двумя студиями на одну дату создаёт одну заявку. Каждый снимок распознаётся отдельно, организация определяется по профилю залов. Неизвестная студия, скрытая граница карточки и неполные записи уточняются для конкретного фото. Совпавшее название зала разных организаций не объединяет записи. Больше двух организаций или разные даты требуют разделения альбома на сайте. У отправителя проверяются права на обе студии.

Одна кнопка «Взять» назначает одного сотрудника на обе части. Публикация, перенос в топик взятых, фотографии в личном чате, снятие, возврат в активные и уведомления об освобождении работают для всей заявки. Завершение происходит по самому позднему окончанию. Фактические работы каждой студии вносятся отдельно; предложения не создают начислений.

Повторный снимок одной студии сравнивается с её частью общего предложения. Подтверждённые «Дополнить» и «Заменить» сохраняют другую студию, её фотографии и назначенного сотрудника. Устаревшая версия требует повторного сравнения. Отдельные предложения не объединяются автоматически.

## API

`POST /api/shifts/ledger/offers/`:

```json
{
  "request_key": "unique-client-key",
  "kind": "shift",
  "date": "2026-10-27",
  "comment": "Один сотрудник на обе студии",
  "parts": [
    {"organization": 1, "start_time": "10:00", "end_time": "18:00"},
    {"organization": 2, "start_time": "16:00", "end_time": "20:00"}
  ]
}
```

Ответ содержит `parts` с ID, названием организации, временем, интервалами записей и `image_ids`. В общем массиве `images` поле `part` связывает фотографию с частью. При загрузке `offers/<id>/image/` в multipart передают `part`, `version`, `message_id`, `image`. Существующий запрос одной организации сохраняется; обычные услуги остаются отдельными предложениями.

Для изменения времени открытой заявки `offers/<id>/edit/` принимает `fields.parts` с ID и организацией изменяемой части. Неуказанная часть сохраняется. Изменение времени занятой заявки через редактор требует сначала снять сотрудника; подтверждённое обновление по скриншоту сохраняет назначение. Для уточнений используется `answers.parts` либо вопрос конкретного снимка/записи. Общий диапазон не снимает вопросы об обрезанных записях. Все действия требуют актуальной `version`.

Фильтр `?organization=<id>` ищет по любой части, возвращая родительскую строку один раз до пагинации. Основные поля организации и времени сохранены для старых клиентов как проекция первой студии и общего диапазона; для отображения условий новой заявки используют `parts`.

## Обновление и совместимость

После резервной копии:

```bash
docker compose --profile bot up -d --build
```

Миграции `ledger 0012` и `offers 0004` выполняются существующим сервисом миграций. Для старых смен с известной организацией создаётся одна часть и привязываются изображения, без повторной публикации, смены статуса, версии и исполнителя. Новые сервисы не нужны.

Новый алгоритм расчёта имеет `pricing_version=2`; `overlap_factor=0.5` означает коэффициент только пересекающегося времени. `actual_hours`, `overlap_hours`, `payable_hours` хранятся отдельно. До уменьшения выбирают студию по общей фактической длительности, полной базе и ID. После уменьшения применяют ограничения тарифа к каждой записи. Ручные решения сохраняют автора, участников и отпечаток интервалов/тарифов. Данные старых периодов автоматически не пересчитываются: используется существующий предпросмотр разницы и подтверждение. Снимки утверждённых счетов и отправленные Excel неизменяемы. Старое распределение одной студии между разными сотрудниками остаётся выключенным.

## Проверки

Результаты проверок записываются в `docs/two-studio-verification.md`. Проверки Telegram используют тестового отправителя, без реальной доставки сообщений.
