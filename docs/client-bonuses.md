# Доплаты по клиентским записям

## Настройка и работа

Откройте **Услуги и тарифы → Правила доплат**. На вкладке **Клиенты** добавьте
название (необязательно) и телефоны, по одному на строку. Один клиент может иметь
несколько номеров; российские `8…` и `+7…` приводятся к одному виду. Один номер
нельзя привязать к двум клиентам, включая одновременное сохранение.

На вкладке **Правила** задайте произвольное название, студию, сумму за отдельную
клиентскую запись и период действия. Отметьте всех клиентов этого правила. Для
исключения клиента снимите его флажок; само правило можно выключить. Сохранение
условий не меняет старые начисления. Нажмите **Проверить и применить**, проверьте
разницу за выбранный период и примените предпросмотр. Это также активирует новое
правило, даже если выполненных работ ещё нет и разница равна нулю. Техническая
ревизия сама по себе не считается финансовым изменением.

На вкладке **Скриншоты** выберите студию, дату и фотографии. Разрешены прошедшие
даты. Изображения проходят через существующую очередь PostgreSQL и локальный
OCR-worker. Распознавание в личном чате бота также собирает сведения о клиентах,
включая повторное расписание без изменений. При неуточнённой дате предложения
клиентские записи ещё не создаются. Для неоднозначных сведений откройте исходное
фото на сайте, исправьте клиента или интервал и подтвердите запись.

Новый снимок создаёт **черновики**, а не доплату. OCR сохраняет только совпадения
полных номеров с зарегистрированными клиентами; прочитанные неизвестные номера и
текст карточек в результатах не сохраняются. Если клиента ещё нет в справочнике,
добавьте его и загрузите снимок повторно либо внесите запись вручную.

На вкладке **Записи клиентов** доступны ручной ввод, исправление, подтверждение,
выбор смены и правила, исключение с причиной, восстановление и история. Восстановленная
запись снова требует подтверждения. Снимки не отменяют записи, которые на них
отсутствуют. Одинаковый клиент, студия, дата и точный интервал в разных залах
объединяются; несколько различных интервалов одного клиента дают отдельные доплаты.
Когда в одной карточке найдено несколько возможных клиентов, подтверждение одного
исключает альтернативные черновики этой карточки.

## Начисление

Подтверждённая клиентская запись сопоставляется только с внесёнными в журнал сменами
малого и большого администратора той же студии и даты. Требуется положительное
пересечение точных интервалов. Соприкосновение границ пересечением не считается.
Плановые предложения не создают работ или заработка.

Если подходящих выполненных смен нет, запись находится в состоянии **Ожидает смену**.
Если сотрудник один, начисление выбирает его запись с самым большим пересечением,
затем самым ранним началом и меньшим ID. При нескольких сотрудниках или правилах
потребуется выбор на сайте. Одной клиентской записи соответствует одно начисление.
Изменение значимых исходных данных делает прежний ручной выбор неактуальным.
Неразрешённые вопросы блокируют подтверждение затронутого счёта.

Итог работы: **база после расчёта пересечений + ручная доплата + клиентские доплаты**.
Клиентские доплаты не делятся и не ограничиваются максимумом тарифа. Они учитываются
в счёте студии и заработке сотрудника. Например, база 1 000 ₽, ручная доплата 500 ₽
и три клиентские записи по 200 ₽ дают 2 100 ₽.

Карточка работы, история и Excel показывают клиентские доплаты отдельно. В отчёте
студии добавлены колонки с суммой и составом; в отчёте заработка при наличии доплат
добавляется лист **Клиентские доплаты**. Телефонные поля туда не экспортируются.
Распознанные номера и имена из текста карточек не добавляются в сообщения топиков.
Исходные фотографии предложений продолжают использовать существующий процесс
публикации фотографий; их содержимое этим изменением не редактируется.

Изменения работ и клиентских записей пересчитываются одной транзакцией. Изменения
правил применяются через проверенный предпросмотр; старые периоды за его пределами
не пересчитываются автоматически. Для исправления работы в подтверждённом счёте
нужен флажок корректировки и новая версия документа. Отправленные Excel сохраняются.
Полученные оплаты, вычеты и отметка «Оплатил» этим процессом не меняются.

## API

Все ресурсы используют существующий административный доступ сайта:

- `GET/POST bonus-clients/`, `GET/PUT bonus-clients/<id>/`;
- `GET/POST bonus-rules/`, `GET/PUT bonus-rules/<id>/`;
- `GET/POST client-bookings/`, `GET/PUT client-bookings/<id>/`;
- `POST client-bookings/<id>/confirm/`, `exclude/`, `restore/`, `choose/`;
- `POST bonus-recalculate/` с `start`, `end`, необязательными `rule`, `revision`,
  `correction`; применение передаёт полученный `fingerprint`;
- `GET/POST client-booking-imports/`, `GET client-booking-imports/<id>/`;
- `GET client-booking-imports/<id>/image/?index=0` — защищённое изображение;
- `POST client-booking-imports/<id>/retry/` с актуальной `revision` после ошибки.

Префикс: `/api/shifts/ledger/`. Изменения клиента, правила, записи и повтор импорта
передают `revision`; выбор смены также передаёт `token`, `record`, `rule`.
Списки клиентов, правил и записей поддерживают `offset`, `limit` (до 100).
Записи фильтруются по `organization`, `client`, `start`, `end`, `state`.
Импорт принимает multipart: `organization`, `date`, несколько файлов `images`
общим размером до 10 МБ. Импортированные фото удаляются после срока хранения 30 дней;
записи, результаты и история остаются в БД. Резервная копия использует прежние БД
и закрытый том `offer_media`.

## Обновление Linux Compose

Новых сервисов нет. Изменяются общий backend-образ, frontend и OCR-образ. Миграции:
`ledger 0014–0015`, `offers 0005–0006`; они не начисляют доплаты старым работам.
После обновления исходников и резервного копирования БД/тома соберите образы последовательно:

```bash
docker compose --profile bot --parallel 1 build backend
docker compose --profile bot --parallel 1 build frontend
docker compose --profile bot --parallel 1 build recognition
docker compose --profile bot run --rm migrate
docker compose --profile bot --parallel 1 up -d --no-build --no-deps backend frontend bot billing offers recognition
docker compose --profile bot ps
docker compose --profile bot logs --tail=100 backend recognition billing offers
```

Переиспользуемые модели остаются внутри OCR-образа и в памяти worker. Интернет для
распознавания не нужен; публикация в Telegram использует прежние сервисы и настройки.
