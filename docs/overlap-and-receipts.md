# Деление смен, доплаты, поступления и вычеты

## Как пользоваться

- В «Журнале работ» у выполненной смены малого или большого администратора можно указать доплату и её причину. Доплата начисляется полностью сверх базы, даже при делении или достижении максимума тарифа.
- При положительном пересечении смен одного сотрудника в двух студиях за одну дату выбирается студия с меньшими суммарными часами. При равных часах выбирается меньшая базовая стоимость без уменьшения, затем меньший ID организации. У выбранной студии только пересекающееся время оплачивается наполовину. Участки пересечения объединяются, одна минута не считается дважды; соприкосновение границ не считается пересечением.
- Почасовой расчёт: фактические часы − половина пересекающихся часов, затем ставка, минимум и максимум отдельно к каждой записи, затем полная доплата. Фиксированные тарифы оплачиваются полностью. Например, 16:00–20:00 с пересечением 16:00–18:00 даёт 3 оплачиваемых часа. При ставке 200 ₽ и минимуме 1 000 ₽ стоимость составляет 1 000 ₽ без доплаты.
- Кнопка «Разобрать пересечение» (½) позволяет выбрать одну, обе или ни одну студию. Для трёх и более связанных студий ручное решение обязательно; до него подтверждение затронутых счетов заблокировано. Изменение исходных смен или тарифа требует нового подтверждения ранее ручного решения. Если точного времени нет, система просит его указать.
- Старое распределение одной смены между разными сотрудниками остаётся отключённым (`SHARED_SHIFT_ALLOCATION_ENABLED=0`). Включать этот флаг для нового правила не требуется: он возвращает прежний алгоритм вместо нового.
- В «Настройки → Организации → Полученные оплаты» доступны поступления и вычеты с датой. Для поступления указывается плательщик, для вычета — причина. Сумма вводится положительной. Итог за выбранный период: получено минус вычеты. Можно исправлять записи и просматривать историю.
- Поступления и вычеты не меняют начисления сотрудникам, стоимость работ, задолженность по счетам и отметку «Оплатил». В Excel организации они вынесены на лист «Полученные оплаты» с отдельными итогами.
- В «Услуги и тарифы → Настроить» есть флажок «Требовать комментарий» и текст «Какой комментарий запросить». Сайт не сохраняет такую услугу без комментария. Бот показывает подсказку и предлагает дополнить исходное сообщение; в мастере `/offer` комментарий также обязателен. Для автоматических ежедневных/ежемесячных начислений требование комментария не поддерживается.

## Обновление

После резервного копирования БД обновите код и выполните обычный запуск:

```bash
docker compose --profile bot up -d --build
```

Сервис миграций применит миграции ledger до 0012. Новая миграция сохраняет фактические, пересекающиеся и оплачиваемые часы и версию алгоритма, без массового пересчёта работ. Старые периоды пересчитываются через «Журнал работ → Предпросмотр пересчёта» и подтверждение. Отображаются только изменения суммы, состояния проверки или исправленные ошибки; заполнение служебных полей не считается изменением стоимости. При изменении исходных данных предпросмотр нужно повторить. Подтверждённые работы требуют режима корректировки; уже отправленные Excel и снимки поступлений сохраняются. Поздние изменения попадут в новую версию счёта.

Общие предложения двух студий и сведения о проверках обновления описаны в [two-studio-offers.md](two-studio-offers.md).

## Проверки реализации

Проверено 29.09.2026:

- 241 серверный тест на отдельном PostgreSQL 18: расчёты, копейки, минимум/максимум, доплаты, ручной выбор, устаревшие данные, конкурентная запись смен, история, снимки документов, поступления и вычеты.
- 34 теста интерфейса, проверка типов и production-сборка Next.js.
- Новая пустая тестовая база успешно прошла все миграции; проверка моделей не требует дополнительных миграций.
- В браузере на отдельной SQLite-базе: сохранение вычета и обновление баланса, ручное решение трёх студий, карточка смены с доплатой и предпросмотром, настройка обязательного комментария. Ошибок в консоли не обнаружено.
- Содержимое Excel, суммы, отдельный лист и неизменность утверждённого файла проверены автоматически через openpyxl. Открытие в настольном Excel не проверялось.
- Ответы бота проверены тестовым отправителем; реальные сообщения в Telegram не отправлялись. Развёртывание на рабочем Linux-сервере в этой проверке не выполнялось.
