# Предложения смен из YCLIENTS

Скриншоты поступают в личный чат Telegram-бота. Сервер распознаёт отдельные записи,
уточняет скрытые значения и предлагает общий диапазон от первого начала до последнего
окончания. После подтверждения отправителем фотографии и кнопка «Взять» появляются
в отдельном топике. Взятие предложения **не создаёт работу, начисление или счёт**.
Фактическое время сотрудник впоследствии вносит в существующий журнал.

Распознавание работает локально: OpenCV и PaddleOCR на CPU. Внешние AI API не
используются. Интернет нужен при сборке образа для зависимостей и весов, а в работе —
боту и процессу публикаций для Telegram. OCR-контейнер подключён только к внутренней
сети с PostgreSQL. Ни скриншоты, ни распознанный текст из него в интернет не отправляются.

**Текущий режим — обязательное подтверждение перед публикацией.** Порог точности
выше 99% при покрытии 90% не доказан. Результаты и ограничения: [отчёт OCR](ocr-validation.md).

## Запуск на Linux

Целевая платформа: Linux amd64, Docker Engine и Docker Compose v2; GPU и Redis не нужны.
Для первоначального стенда предусмотрите 2–4 CPU и 4 ГБ RAM на весь стек, свободное
место под образы, PostgreSQL и изображения. Это стартовая рекомендация, а не измеренный
минимум: на целевом сервере обязательно повторите проверку задержки и памяти.

1. Перенесите исходники, исключив `.env`, `.venv`, `node_modules`, локальные модели,
   тестовые базы и пользовательские архивы. Скопируйте `.env.example` в `.env`.
2. Заполните `POSTGRES_PASSWORD`, `DJANGO_SECRET_KEY`, `TELEGRAM_BOT_TOKEN`, параметры
   существующей Basic Auth и домена. Для HTTPS задайте `APP_DOMAIN=ваш-домен`,
   `SITE_URL=https://ваш-домен`, добавьте домен в `DJANGO_ALLOWED_HOSTS` и
   `DJANGO_CSRF_TRUSTED_ORIGINS`. Не публикуйте порты backend, frontend или PostgreSQL
   в обход Caddy. Оставьте `DJANGO_API_BASE_URL=http://backend:8000`.
3. Оставьте `OFFER_AUTO_PUBLISH=0`, `OFFER_MEDIA_ROOT=/app/offer_media`,
   `OFFER_OCR_THREADS=2`. `DJANGO_TIME_ZONE` по умолчанию — `Asia/Yekaterinburg`;
   для другой зоны задайте одинаковое значение для всего стека.
4. Выполните из корня проекта:

   ```sh
   docker compose --profile bot up -d --build
   docker compose --profile bot ps
   ```

Первичная сборка скачивает закреплённые модели, проверяет SHA-256 и выполняет пробное
распознавание. Она занимает дольше обычного старта. Сервис `migrate` должен завершиться
успешно, после него стартуют новые процессы. `recognition` считается готовым только
после загрузки весов, пробного распознавания и записи сигнала в БД; `offers` — после
успешного обращения к очереди. Модели остаются в памяти до перезапуска процесса.
Отсутствующий токен не позволяет запустить публикации.

| Сервис | Назначение | Доступ |
|---|---|---|
| `recognition` | Структура календаря, OCR, вопросы | БД и закрытый том; без внешней сети |
| `offers` | Доставка, обновление кнопок, завершение, очистка | БД, закрытый том, Telegram |
| `bot` | Приём фото, ответы и нажатия | Существующий бот; закрытый том |
| `backend` | Сайт и защищённая выдача изображений | Через Caddy/Next.js |

Новые сервисы включены в профиль `bot`; остальные сервисы PostgreSQL, Django, Next.js,
Caddy, billing и необязательный sync сохранены. Все работающие с медиа контейнеры
используют UID 1000. Именованный том `offer_media` получает владельца из образа.
Если вместо тома используется каталог хоста, его владельцем должен быть UID 1000;
не открывайте его через Caddy и не устанавливайте права `777`.

## Первичная настройка на сайте

1. Главный администратор, отправители и сотрудники пишут боту `/start`. В существующих
   настройках выберите утверждающего счетов — это главный администратор предложений.
2. В «Предложения смен → Залы и разрешения» загрузите эталон для каждой организации.
   После обработки остаётся только верхняя часть с залами, исходный эталон удаляется.
   Если OCR не нашёл названия, их можно заполнить вручную.
3. Проверьте каждое название. Сокращения вводятся через `|`, каждый зал с новой строки:

   ```text
   БОХО
   Модерн
   INLIGHT
   Стол визажный | Стол ви… | Стол ви...
   ```

   Отметьте «Названия и сокращения проверены» и сохраните. Неоднозначные совпадения
   между организациями требуют ответа отправителя. Эталон не обучает новую нейросеть:
   он помогает задать и проверить профиль названий.
4. Укажите разрешённых отправителей флажками в профиле каждой организации.
   Главный администратор имеет доступ ко всем активным организациям. Отзыв разрешения
   проверяется снова перед публикацией, включая уже поставленные в очередь заявки.
5. В «Настройки → Telegram и расписание» укажите ID группы и отдельного топика предложений, разрешите боту
   отправлять фотографии и сообщения. Топик услуг/расходов здесь использовать нельзя.
   Включите приём. В «Настройки → Команда» привяжите сотрудников к пользователям,
   написавшим боту `/start`. Состояние обработчиков и режим подтверждения доступны
   в «Предложения смен → Обработка».

## Работа с предложениями

- Отправитель присылает фото либо альбом до 10 изображений, каждое до 10 МБ.
  Поддерживаются JPEG, PNG, WebP; лимит декодированного изображения — 20 Мп.
  Первая непустая подпись становится комментарием. Повтор доставки того же сообщения
  не создаёт новую заявку; одинаковые изображения не публикуются дважды в альбоме.
- Распознаются клиентские карточки независимо от цвета их тела. Штрихованные
  блокировки не включаются. Текст времени сверяется с сеткой. Невидимое окончание
  не берётся из соседней блокировки или длительности услуги.
- Вопросы приходят отдельными сообщениями. Используйте Telegram «Ответить» именно
  на сообщение с вопросом. Для интервалов: `13:00–16:00, 16:30–20:00`; для даты:
  `12.09.2026`. Все ошибки формата нужно исправить, частичный ответ не отбрасывается молча.
- Если в альбоме несколько дат или организаций, откройте заявку на сайте и назначьте
  каждому фото группу. Будут созданы отдельные предложения с историей происхождения.
- Год выбирается по ближайшей дате, сомнительная или прошедшая дата требует проверки.
  До публикации можно исправить итоговый диапазон. Уже прошедшее начало публиковать нельзя.
- После подтверждения сначала отправляются фото, затем отдельное управляющее сообщение.
  «Взять» доступно активным сотрудникам с Telegram ID. При одновременных нажатиях
  побеждает одна транзакция; старые кнопки отклоняются. Пересекающиеся взятые предложения
  одного сотрудника запрещены.
- После взятия в топике виден сотрудник, общая кнопка исчезает. В личные чаты приходят
  «Сняться» сотруднику и «Снять со смены» администратору. Снятие возвращает общую кнопку.
  Менять дату/время занятого предложения можно после снятия сотрудника; комментарий — сразу.
- По окончании диапазона занятое предложение завершается, свободное истекает. Есть
  ручная отмена. Проверка сроков выполняется примерно раз в 30 секунд работающим `offers`.

На сайте доступны фильтры, исходные фотографии, отдельные интервалы, ответы, исправления,
назначение, снятие, отмена и история изменений. Изображения выдаются только через тот же
защищённый сайт; прокси передаёт multipart и PNG без преобразования в текст.

## Восстановление после сбоев

OCR выполняется вне транзакции. Короткие транзакции под существующей блокировкой
журнала получают задание и сохраняют результат. Версия заявки и номер попытки не дают
старому процессу перезаписать уточнения или поздно полученную часть альбома. Через
3 минуты прерванное задание возвращается в очередь; после трёх попыток показывается
ошибка и доступен ручной повтор. Для запуска нескольких экземпляров нужен PostgreSQL.

Отправки Telegram имеют отдельную долговечную очередь. Если ответ Telegram потерян,
доставка получает статус `unknown`: автоматического повтора создания сообщения нет.
Откройте «Проверка доставки», проверьте нужный чат и либо внесите ID найденных сообщений,
либо явно подтвердите, что сообщений нет. Для альбома внесите ID всех его фотографий.
Не нажимайте повтор до проверки: Telegram не предоставляет идемпотентный ключ отправки.

Обновление уже известного сообщения безопасно повторяется автоматически при временном
сбое. Если Telegram окончательно отказал, сайт показывает ошибку и кнопку повтора
обновления после восстановления доступа. Если сообщение удалено, отмените предложение
и создайте новое. Проверка на сервере отклоняет устаревшие кнопки, даже если Telegram
пока не удалось обновить. Доставка неизвестного состояния не блокирует остальные заявки.

Файлы предложений удаляются через 30 дней после завершения, отмены, истечения или
пометки повтора. Необработанные частные черновики после 30 дней без изменений отменяются,
а файлы удаляются ещё через 30 дней. Оригиналы эталонов, оставшиеся из-за сбоя, и
бесхозные временные файлы очищаются через сутки. Опубликованные фото остаются в Telegram.
Распознанные имена/телефоны клиентов не сохраняются в структуре результата; исходные
фото до очистки содержат их. Комментарий отправителя сохраняется как введённый текст.

## Обновление и резервные копии

Перед обновлением используйте согласованную копию БД **и** медиа:

```sh
sh deploy/backup-offers.sh
```

Скрипт кратковременно останавливает только запущенные пишущие сервисы, создаёт
`backups/offers_ДАТА/database.sql.gz`, `offer_media.tar.gz`, контрольные суммы и список
образов, затем возвращает ранее работавшие процессы. Во время копирования сайт временно
не принимает изменения. Каталог имеет закрытые права. Храните `.env` отдельно в защищённом
хранилище; архив содержит данные клиентов, поэтому применяйте срок хранения и к копиям.

После резервной копии обновите исходники и выполните обычную команду запуска с `--build`.
Проверьте успешную миграцию и готовность фоновых сервисов. Перед первым включением профиля
`bot` также проверьте существующее расписание billing: оно продолжает работать как раньше.
Для отката используйте согласованные версии исходников, образов и резервной копии;
не запускайте старую версию поверх новой схемы БД без проверки совместимости.

### Восстановление копии

Сначала восстановите на отдельном Linux-стенде/в новом Compose-проекте с пустыми томами.
Старые тома и рабочую установку сохраните. Не подключайте второй экземпляр бота с тем же
токеном одновременно. Ниже команды для **пустой** БД; в существующую базу их выполнять нельзя.
Задайте `BACKUP` абсолютным путём к выбранному каталогу копии:

```sh
export BACKUP=/srv/backups/offers_YYYY-MM-DD_HH-MM-SS
(cd "$BACKUP" && sha256sum -c SHA256SUMS)
docker compose build backend recognition
docker compose up -d db
# Дождитесь healthy у db. Прочие сервисы пока не запускайте.
gzip -dc "$BACKUP/database.sql.gz" > "$BACKUP/restore.sql"
docker compose exec -T db sh -c 'psql -v ON_ERROR_STOP=1 -U "$POSTGRES_USER" -d "$POSTGRES_DB"' < "$BACKUP/restore.sql"
docker compose run --rm --no-deps -T backend tar -C /app/offer_media -xzf - < "$BACKUP/offer_media.tar.gz"
docker compose run --rm --no-deps backend python manage.py migrate --noinput
docker compose run --rm --no-deps backend python manage.py prepare_offer_restore
```

`prepare_offer_restore` переводит неотправленные/прерванные доставки из старой копии
в неопределённые: Telegram мог получить сообщения после момента резервирования.
Он также возвращает задания OCR в очередь. Затем запустите сайт, оставив бота и workers
выключенными: `docker compose up -d backend frontend caddy`. Сверьте назначения, отмены
и доставки с Telegram; изменения после даты копии в БД отсутствуют. Уберите временный
`restore.sql` после проверки копии. Проверьте также существующие доставки счетов.
После сверки выполните `docker compose --profile bot up -d --build`.

## Проверка перед рабочим запуском

На отдельном стенде с тестовым ботом:

```sh
sh deploy/smoke-offers.sh
```

Скрипт проверяет Compose, миграции, Django-тесты (включая конкурентное взятие в PostgreSQL),
загрузку весов с запрещёнными сетевыми соединениями и готовность workers. Для прогона
архива задайте `OFFER_TEST_ARCHIVE=/абсолютный/путь/DS.zip`. Скрипт не рассылает тестовые
сообщения реальным людям. Обычные workers тестового стенда работают только с его токеном.

Дополнительно проверьте вручную:

1. Без Basic Auth сайт и URL картинки недоступны. Эталон загружается через публичный
   HTTPS-адрес, после OCR видны только заловые заголовки. Ответ на картинку — `image/png`.
2. Два фото одного дня → вопросы → ответ → подтверждение → фото и кнопка в тестовом топике.
   Для примера 12 сентября подтвердите окончание второй записи: `20:00`; итог `13:00–20:00`.
3. Два тестовых сотрудника одновременно нажимают «Взять»: одно назначение. Снятие обоими
   способами, повтор старого нажатия, запрет чужого отправителя и отозванного разрешения.
4. Остановка и запуск OCR при задании, поздняя часть альбома, повтор Telegram update,
   отмена во время доставки, неопределённая отправка и ручная сверка.
5. На предложении с близким окончанием — автоматическое завершение/истечение; в тестовой
   базе для закрытого предложения старше 30 дней — удаление локальных файлов.
6. Измерьте на целевом CPU время от последнего фото альбома до **содержательного** ответа
   в Telegram, включая очередь и загрузку. Цель для двух фото — до 10 секунд. Учитывайте
   параллельные отправки: один OCR-worker обрабатывает задания последовательно.

## API и модели

Все маршруты находятся под `/api/shifts/ledger/` и используют существующую защиту сайта.
Изменяющие действия предложения принимают `version` из последнего GET, иначе возвращают
ошибку. Для `answer` передаётся `answers`, для `edit` — `fields`.

| Маршрут | Метод / назначение |
|---|---|
| `offer-config/` | GET, POST: отдельный топик, включение, готовность |
| `offer-profiles/` | GET: профили |
| `offer-profiles/<organization>/` | POST: залы, алиасы, подтверждение, контакты |
| `offer-profiles/<organization>/sample/` | POST multipart `image`: эталон |
| `offer-profiles/<organization>/header/` | GET: закрытое изображение заголовка |
| `offers/` | GET: `state`, `organization`, `date`, `offset`, страницы по 50 |
| `offers/<id>/` | GET: карточка, фото, вопросы, очередь и история |
| `offers/<id>/<action>/` | POST: `answer`, `publish`, `assign`, `release`, `cancel`, `edit`, `retry`, `split`, `delivery` |
| `offer-images/<id>/` | GET: закрытое изображение |

Сущности: `RecognitionProfile`, `ShiftOffer`, `OfferImage`, `RecognitionJob`,
`OfferDelivery`, `OfferMessageEdit`, `WorkerHeartbeat`, `OfferConfig`. Изменения отражаются
в существующем `AuditLog`; автор Telegram сохраняется, действия сайта имеют актор `web`
в соответствии с общей административной авторизацией проекта. История и сведения о
доставке остаются после удаления файлов. Данные журнала работ не используются как
хранилище плановых предложений.

Закреплённые OCR-зависимости — `backend/requirements-ocr.txt`, полный набор ограничений
версий для Linux/Python 3.12 — `backend/requirements-ocr-linux.lock`, URL и SHA-256 весов —
`backend/scripts/ocr-models.json`. Источники: официальные проекты
[PaddleOCR](https://github.com/PaddlePaddle/PaddleOCR),
[PaddlePaddle](https://github.com/PaddlePaddle/Paddle),
[OpenCV](https://github.com/opencv/opencv). Веса — детектор PP-OCRv5 mobile и
распознаватель eslav PP-OCRv5 mobile. Это интеграция существующих локальных компонентов
с собственными правилами календаря, очередью и рабочим процессом, без обучения с нуля.
